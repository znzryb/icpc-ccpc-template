# PR（Pull Request）写法

本仓库的 PR 标题、正文、提交信息一律用**中文**（代码标识符、命令、文件名保持原样）。
已经有 PR 的分支继续往上推提交即可，用 `update_pull_request` 改描述，不要再开一个 PR。

## 正文固定五段

1. **动机**：为什么要改，改之前哪里不好。用户提出需求时给的**图片**（截图、手绘、聊天记录截图）
   必须放在这一段，配一句话说明图里是什么。
2. **改动**：做了什么，按模块或文件分点；行为 / 接口有变化的单独说明。
3. **效果**：改完以后能看到的东西**尽量配图**，越多越好，但每张图都要有一句说明。常见的图：
   - 编译出来的 PDF 页面截图（有 xelatex 的机器上重编后截）；
   - 代码前后对比截图；
   - 跑出来的结果图（几何题画出凸包 / 最小圆 / 半平面交等）；
   - 缩减统计、性能对比之类的图表。
4. **验证**：跑了什么命令、结果数字是多少（如"1720 个对拍用例通过、23 个依赖组合编译通过"）。
5. **待办**：这次没做完、需要别人接着做的事明确列出来（如"PDF 未重编"、"Espanso 未同步"）。

## 图片怎么放

仓库没有外部图床，PR 里用到的图片（包括用户给的需求图）统一提交到
`.github/pr-assets/<主题>/`，文件名用英文短横线（如 `size-before-after.png`）。
在 PR 正文里用**带 commit SHA 的 raw 链接**引用，分支删掉之后链接仍然有效：

```
![说明](https://raw.githubusercontent.com/znzryb/icpc-ccpc-template/<commit-sha>/.github/pr-assets/<主题>/<文件名>.png)
```

图片加进仓库后要先 push，拿到 SHA 再写进 PR 描述。图片控制在 1 MB 以内，宽度 1200–1600 px 即可。

## 示例骨架

```markdown
## 动机
（一两段话 + 需求图片）

## 改动
- ...

## 效果
![改动前后对比](...)
说明：...

## 验证
- `python template-check/geometry/run.py`：1720 用例通过

## 待办
- [ ] ...
```
